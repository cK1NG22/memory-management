Memory has 4 separate layers:

- Rules: loaded every session. The plugin can't install them, so copy rules/common plus ONE language pack you actually use into ~/.claude/rules/ecc/. Each extra pack costs context every session.
- Session memory: hooks save a summary as you go and load the last 7 days at session start. /save-session and /resume-session are for handoffs you control.
- Instincts: tool calls get logged, and a background observer turns your corrections and repeated patterns into small trigger/action instincts with confidence scores. The top few get injected each session. Big gotcha: the observer ships turned OFF (observer.enabled in skills/continuous-learning-v2/config.json), so nothing is learned until you turn it on. Most videos get this wrong.
- Memory Vault (optional): portable markdown memory shared across tools. Needs the npm package installed separately.

Skills: almost all of them are model-invoked, so no, you don't need to know them all. Claude matches a task to a skill on its own, and you can force one with /skill-name. Name the skill when it matters, since Claude sometimes falls back to its default behavior.

Learn these day one: /ecc:plan, tdd-workflow, /code-review, /build-fix, /save-session, /resume-session. Use /ecc:ecc-guide when you're curious about anything else.

Watch out for bloat: a full install puts about 27k tokens of skill descriptions in every session. If it feels heavy, reinstall with a profile (like "developer") instead of the full plugin.

Agents: loosely linked to skills, not hard-wired. None of the 68 agents preload specific skills. Their prompts point to relevant ones by name, and any agent can use any installed skill. The pairing really happens at the workflow level (/ecc:plan uses the planner, /code-review uses code-reviewer, and so on), and rules tell Claude to use some agents automatically, like planner for complex features and code-reviewer after changes.

There are six install profiles: minimal, core, developer, security, research, and full.

- minimal: the lightest option, with no hooks, so no session memory or instincts
- developer: picks skills for your stack. One reviewer on TypeScript got 121 of the ~281 skills.
- full: everything, the same as the plugin install (the ~27k token one)

Quick correction first: developer doesn't tailor itself to your stack. It's a fixed bundle that includes every framework's skills.

Every profile includes all 68 agents, all commands, rules, and a core pack of ~47 workflow skills (tdd-workflow, verification-loop, continuous-learning-v2, ecc-guide, etc.). The difference is what's on top:

- minimal (~48 skills): no hooks at all, so no session memory and no instincts. Just agents and commands.
- core (~48 skills): minimal plus hooks, so session memory and instincts work. The lean pick if you want memory.
- developer (~125 skills): core plus every language/framework skill (React, Python, Go, Rust...), database skills, and worktree/tmux orchestration. The repo calls it the default for most users.
- security (~67): core plus security review/scanning and compliance skills.
- research (~74): core plus deep research, writing, SEO, market research, and social posting. For non-coding work.
- full (all 292): everything. Same as the plugin install.

Separate setting worth knowing: hook profiles (minimal / standard / strict, default standard). Minimal keeps session memory but turns off instinct learning. Standard adds instincts plus quality checks. Strict adds pre-commit and push-review checks.

You can also mix, like --profile core --with <module>, to add just what you need.

Do you think it is simplest to use the plugin or should I manually manage / choose what I download? I don’t want a heavy maintenance burden

For low maintenance, I'd go with the plugin. Updates come through Claude Code, and you never have to track what you copied where.
The tradeoff is weight: the plugin installs all ~292 skills, about 27k tokens of context every session. Two small manual steps either way: copy rules/common plus your one language pack, and turn on the observer if you want instincts.
My take: start with the plugin. If sessions start feeling slow or context runs out early, switch to a core profile install then. Just don't run both at once, or everything gets duplicated.

Instinct:
	Short version: nothing auto-updates in the background, either way. And a correction to what I said earlier: the repo doesn't say the plugin updates through Claude Code. Both paths are "rerun one command when you want the new version."
	Core install:
- You keep a git clone of the repo. To update, run ecc auto-update (manual despite the name), which pulls the latest and reinstalls your same profile.
- It tracks every file it installed, so ecc doctor finds anything broken or changed and ecc repair fixes it.
- Rules update along with it.

Plugin:
- Update by rerunning the setup command (npx ecc-universal@<new version> setup) or /ecc:configure-ecc. No clone to keep around.
- Rules you copied by hand never update. You re-copy them when you want newer ones.

Either way: releases land about every 2-4 weeks. Don't edit ECC's own files, since updates overwrite them. Put your customizations in your own files, which ECC never touches.

Maintenance is about the same for both, so the real call is lean (core) vs one-command simple (plugin).
